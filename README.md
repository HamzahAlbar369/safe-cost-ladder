# engine — Deliver AI with Less Compute (HUMAIN × Misk Hackathon, Challenge 2)

An efficiency layer that answers each request with the cheapest (model, effort) configuration that still
meets the task's accuracy floor and latency budget, and proves the savings on held-out data.

> **Fiction disclaimer.** The showcase workload is a *fictional* motor-insurance claims desk
> ("Oasis Motor Insurance (fictional demo insurer)"). Its rules are invented for this demo and are not
> real Najm, SAMA or insurer rules.

Status: Phase 2 (dev matrix recorded, floors frozen). See `docs/SPEC.md` and `docs/DECISIONS.md`.

```
uv sync
uv run engine check
```

## Known limitations

- **Name clashes in the synthetic tickets.** The ticket generator reuses the caller's first name for any named
  driver other than the policyholder, and draws the claimant's name independently from the same 20 names, so in a
  small number of tickets two different people share a first name. In one dev ticket this made the right answer
  genuinely ambiguous and fooled most configs. The data were left unchanged (decision D2.9); per-split counts,
  including how many tickets' gold labels depend on the driver's identity, are generated by `engine audit-names`
  and stored in `reports/phase2/name_collisions.txt`. See `docs/SOLVABILITY.md`.
- **Verifiers V0-V2 are weak on rule-interaction errors.** They catch malformed output, ungrounded values and
  self-inconsistent payouts, not a wrong rule applied consistently (`reports/phase2/verifiers.txt`).
